# 剧情助手：剧情聊天、参谋多线路与世界书选择集成计划

## 1. 计划来源与范围裁决

本版计划依据助手最新确认的产品范围，取代此前“五类能力”计划：

- APP 展示名称：**剧情助手**；内部模块标识继续使用 `story-oracle`，不改已有文件名和存储主键。
- 只保留两个用户可见模式：**剧情聊天**、**剧情参谋**。
- 保留一个应用内“选择世界书”入口。世界书是剧情聊天/参谋的上下文来源，不是独立阅读或编辑模式。
- 保留上游原有的剧情讨论多方案互动；参谋可以产生多条剧情线路，并允许多条线路同时启用、同时注入主聊天。
- CSS 只使用宿主现有 token、class 和弹层/按钮/列表组件，不复制上游 `style.css`，不运行时远程加载资源。

明确排除：角色工坊、回复校正、MVU 变量状态诊断/编辑、世界书正文写回、角色资料写回、主聊天消息写回、后台自动任务和后台保活。

## 2. 已确认现状与实施前风险

当前已有 `src/story-oracle.js` 的剧情问答、`advisor` 模式、独立侧聊存储、世界书上下文读取、生命周期接线和持久化门禁；当前文件还存在一次未完成的“剧情助手”改名/删除 `lorebook` 分支改动，实施前必须精读当前文件并做精确差异修复，禁止 reset 或覆盖其他工作区变更。

宿主上下文层已经支持按书名限制世界书读取：`src/host-context.js` 接收 `worldBookNames`，并将其传给 `buildWorldBookContext`；因此目标链路是“应用内选择 → 当前 `storageId` 状态 → `worldBookNames` → `gatherContext`”，不改宿主全局世界书配置。

上游快照已确认存在 `<StoryPlan>` 多方案结构和 `parseStoryPlans`/方案控制逻辑，但本地尚未形成可直接复用的解析器。实施前必须冻结上游 v1.71.0 的字段、容错、采纳和清理语义；无法核实的字段不得臆造。

最大新增风险是：现有计划只描述“点击一个选项继续下一轮”，没有描述“多条线路同时启用并注入主聊天”。本版将两者拆开：**继续讨论**不改变主聊天注入；**启用线路**才改变当前聊天的运行时扩展提示。

## 3. 目标数据与接口契约

### 3.1 剧情聊天

- 读取当前有效聊天的角色资料、最近对话、用户选择的世界书上下文和剧情聊天历史。
- 普通剧情聊天只回答事实、关系、设定和情节问题，不自动续写正文，不写回主聊天。
- 使用当前 `storageId` 隔离侧聊历史；切换聊天、切换页面和关闭请求时旧结果不得污染新 scope。

### 3.2 剧情参谋与多线路

一次参谋回复可包含多个独立 `<StoryPlan>` 方案。每个方案在本地归一化为独立线路，至少包含：

- 稳定本地 `id`；
- 展示标题/目标；
- 线路说明或幕后引导内容；
- 来源参谋消息标识；
- 创建时间与稳定排序；
- `enabled` 启用状态；
- 生成时使用的世界书选择快照标识。

线路动作必须区分：

- **继续讨论**：把该线路作为下一轮参谋请求的明确目标，不写入主聊天注入。
- **启用线路**：将该线路加入当前 `storageId` 的活动线路集合，并重建主聊天扩展提示。
- **停用线路**：从活动集合移除并重建扩展提示。
- **删除线路**：删除线路记录并确保它不再注入。
- **清空线路**：清除当前聊天的所有线路并清空该聊天的扩展提示。

多条 `enabled` 线路必须在同一次主聊天生成中同时注入，使用稳定顺序和明确分隔；不得直接把整个 AI 气泡或未经筛选的 `<StoryPlan>` 原文塞进主提示词。线路之间出现冲突时不替用户静默裁决，保留各线路、显示冲突/并行状态或明确按顺序注入。

注入目标必须是已确认的宿主扩展提示接口（如 `setExtensionPrompt` 或等价现有适配层），不是新增主聊天消息。实施前若宿主没有可确认的设置、更新和清理契约，必须停在适配层并报告，不伪造“已注入”。

默认线路上限暂定为 **5 条同时启用线路**，超过上限时明确提示用户停用旧线路；该上限用于防止提示词无限膨胀，不允许静默丢弃线路。若助手要求无上限，需在实施前重新确认预算策略。

### 3.3 世界书选择

- 页面提供“选择世界书”入口，打开宿主现有 `pm-modal`/`pm-modal-wide`/`pm-modal-header`/`pm-modal-scroll` 风格的应用内面板。
- 面板只展示当前聊天实际可读的书名和勾选状态；不调用设置页的写回逻辑，不修改 `window.__pmWorldBookConfig` 或宿主世界书正文。
- 默认没有应用侧选择记录时，沿用当前聊天可读集合，避免首次使用意外减少上下文；用户明确保存选择后，只向 AI 提供选中的可读书籍。
- 选择状态按 `storageId` 保存，至少记录书名集合、来源 scope/快照标识和更新时间。
- 选择变更只影响后续剧情聊天/参谋请求；已存在线路不自动重写，显示其来源选择已变化的状态，是否继续启用由用户决定。
- 书籍不存在、无权限、读取失败、损坏选择和预算截断都必须有可诊断状态；不可读书名不得进入最终 AI 上下文。

## 4. 持久化与兼容方案

优先扩展现有 Story Oracle store，新增选择状态和参谋线路字段，并定义明确 schema 版本。旧版仅含 `version + scopes + modes` 的数据必须迁移读取，保留所有既有聊天记录；缺少新字段时使用默认选择策略和空线路集合。

迁移不得静默覆盖原始数据：先在内存中完成兼容归一化，只有用户明确保存世界书选择、启用/停用/删除线路或新增侧聊消息时才通过现有 `writeHandle + saveQueue + shouldWrite` 写入。主存储损坏时继续只读保护，不能用空数据覆盖原数据。

若最终证明扩展现有 schema 会破坏当前恢复逻辑，才改用独立版本化选择/线路键；无论哪种方案，都必须登记 `clearPluginData` 清理键、localStorage fallback、隔离测试和回滚方式。

## 5. 分阶段实施

### 阶段 A：契约冻结与当前半成品修复

1. 读取当前 `story-oracle`、模型、存储、世界书配置/上下文、宿主扩展提示和清理清单；建立当前 diff。
2. 核实上游 v1.71.0 的 `StoryPlan` 字段、多个方案解析、方案控制、采纳/停用、扩展提示更新和清理语义；冻结兼容范围。
3. 确认宿主扩展提示 API 的 owner、调用参数、更新方式、跨聊天清理和卸载行为。
4. 确认持久化 schema 版本与旧数据迁移路径；未确认的写回/注入契约不得进入后续实现。

### 阶段 B：页面收敛与产品命名

1. 桌面图标、页面标题、提示文案和 ARIA 标签统一改为“剧情助手”。
2. 删除用户可见的独立 `lorebook` 模式、筛选列表和预览入口；保留安全的世界书读取能力作为上下文和选择面板数据源。
3. 页面只保留“剧情聊天”“剧情参谋”两个模式，以及“选择世界书”入口、停止、返回、清空和状态反馈。
4. 修复当前半成品引用，确保移除 `lorebook` 后无未定义函数、状态或事件分支。

### 阶段 C：世界书选择与上下文注入

1. 派生当前聊天可读书目，按宿主权限、scope 和现有世界书配置过滤。
2. 实现应用内选择面板、草稿勾选、保存/取消、恢复、无书和读取失败状态。
3. 将已保存选择传入 `gatherContext` 的 `worldBookNames`，同时保留上下文预算和 AbortSignal。
4. 覆盖跨聊天隔离、旧 schema、损坏选择、不可读书名剔除、选择变更竞态和 AI 请求只使用当前选择。

### 阶段 D：参谋多方案与多线路注入

1. 实现与上游语义兼容的 `<StoryPlan>` 多方案解析；非法、重复、超限或不完整方案安全降级为普通参谋文本。
2. 参谋回复渲染多个线路卡片，所有标题、目标、说明和属性经过 HTML/属性转义；复用宿主现有按钮、列表、弹层、焦点和禁用态。
3. 实现继续讨论、启用、停用、删除、清空和重复点击保护；所有动作接入当前请求/页面/聊天竞态门禁。
4. 建立活动线路集合的稳定合并器：按 `enabled + order` 生成单一扩展提示，保留线路边界和来源信息，超出预算时明确拒绝或提示，不静默裁剪。
5. 在聊天切换、线路变更、手机关闭、扩展销毁、异常和恢复时验证注入清理与重建。手机 UI 关闭不应无故清除用户已启用且属于当前聊天的线路；聊天切换必须先清旧 scope 再应用新 scope。

### 阶段 E：验证与交付

1. 串行执行 `node --check`、`npm run build`、`npm run check`、Story Oracle 专项检查和 `git diff --check`。
2. 增加纯逻辑测试：世界书选择归一化/迁移、书籍过滤、上下文参数、`StoryPlan` 多方案解析、非法降级、线路启停删除、稳定合并和预算拒绝。
3. 增加异步测试：慢请求取消、旧请求晚返回、选择变更、模式切换、聊天切换、页面关闭、保存失败后队列恢复和注入清理。
4. 检查构建产物确实包含“剧情助手”、两个模式、世界书入口和多线路注入逻辑，避免只改源码而发布旧 bundle。
5. 完成本地代码验收和自动门禁；真实宿主打开/返回/关闭/实际模型效果作为助手现场验收项，不再因为主会话无法替助手操作宿主而无限循环。

## 6. CSS、性能与安全约束

- 只使用现有手机 token、`pm-modal`、`pm-modal-wide`、`pm-modal-header`、`pm-modal-scroll`、`pm-action-button`、`pm-action-row`、`pm-li`、现有表单和状态 class；不复制上游 CSS。
- 新增 UI 修改前必须遵守 `docs/CSS-TOKENS.md` 与 `docs/BASELINE.md`；不新增未登记裸颜色、字号、间距、阴影、z-index 或动画。
- 覆盖亮色/暗色、focus-visible、disabled、loading、窄屏和 reduced-motion；线路卡和书目选择必须保持可触控和可键盘操作。
- 所有用户输入、世界书名称、线路字段、模型输出和 DOM 属性都必须转义；结构化区块只在字符串解析后安全渲染。
- 世界书和线路注入受字符/上下文预算约束；不把 API key、宿主写入句柄或无关完整凭据传给模型；不执行上下文中的命令文本。
- 线路提示更新必须可观测：失败、未确认宿主 API、预算不足和清理失败都要显示可诊断状态并保留原状态。

## 7. 验收标准

- 桌面入口和页面名称均为“剧情助手”，页面只出现剧情聊天和剧情参谋两个模式。
- 用户可以从“选择世界书”入口选择当前聊天可读书籍；选择按 `storageId` 恢复，只影响后续 AI 上下文，不修改宿主世界书。
- 剧情聊天能基于当前聊天、选定世界书和侧聊历史回答，不写主聊天。
- 剧情参谋能一次展示多个合法线路；每条线路可继续讨论、启用、停用、删除，多条启用线路能在同一次主聊天生成中同时注入。
- 线路注入不是主聊天消息写回；聊天切换会清理旧线路注入，线路变更会立即重建，手机关闭不会无故丢失已启用线路，扩展销毁会清理运行时残留。
- 非法/重复/超限/截断 `StoryPlan` 安全降级，不执行猜测性动作；迟到请求和旧线路不能污染当前页面、历史或主聊天注入。
- 旧 Story Oracle 历史可兼容恢复，损坏数据不静默覆盖；清理键、fallback 和回滚路径明确。
- 所有新增 UI 使用宿主 CSS 体系，输入/输出/属性经过转义，API key 和内部句柄不泄漏。
- 构建、专项检查、全量检查、差异检查和本地独立代码验收有真实记录；现场宿主验证单独列为交付后验收清单。

## 8. 回滚与未决假设

- 回滚优先关闭桌面入口、停用线路注入适配器并保留 Story Oracle 历史和用户世界书选择；不得删除宿主聊天、世界书或其他应用数据。
- 若扩展提示 API 或其清理契约无法确认，回滚到“参谋多方案预览 + 继续讨论”，暂不提供“启用并注入”，不得伪造成功。
- 若上游 `StoryPlan` 字段与当前快照不一致，保留普通参谋文本并将解析器置为安全降级，不静默丢弃原文。
- 暂定同时启用线路上限为 5；这是预算保护假设，不是上游事实。若助手不接受该限制，必须在实现前确认基于 token/字符预算的替代策略。
- 真实宿主运行证据由助手现场验收，不作为本地计划执行的无限阻塞条件。
