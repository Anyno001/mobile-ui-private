# Story Oracle 路线工作台与 TASKOW 风格 UI 重构实施计划

## 1. 计划来源

本计划依据已确认设计文档：`.limcode/design/story-oracle-phone-app.md`。

该设计文档已确认：第二轮路线必须进入当前视觉范围；路线工作台与普通会话区分离；视觉采用 TASKOW 风格的白底、深蓝主操作、弱化信息层级、强垂直留白和无装饰性描边；不改变 Story Oracle 存储版本、宿主注入命名空间或其他模块边界。

## 2. 目标与边界

### 目标

- 第二轮及后续参谋回复保存后，路线数据不被覆盖，并能在当前页面立即看到；
- 本轮解析出几条路线必须有明确收据，不能用“已保存”掩盖“没有生成可操作路线”；
- 活动路线逐条纵向显示，长标题完整换行；
- 用户消息、助手说明、路线工作项和输入区职责清晰；
- 剧情助手脱离普通会话气泡视觉，形成独立路线工作台；
- 删除操作使用低强调危险样式，唯一主操作为开始/停止引导或发送；
- `index.js` 必须由源码重建并包含实际改动。

### 不在本计划内

- 不修改 `STORY_ORACLE_STORE_VERSION`，不设计迁移；
- 不修改主聊天消息、世界书正文、角色资料或其他模块存储；
- 不改变 `setExtensionPrompt` 参数和 Story Oracle 注入 key；
- 不复制 TASKOW 业务文案或图片资源；
- 不在本轮扩大到真实宿主全量验收、性能基准或复杂边缘兼容。

## 3. 实施顺序

### 阶段 A：数据链路与契约冻结

1. 精读 `src/story-oracle-model.js`、`src/story-oracle.js`、`src/story-oracle-storage.js`、`src/phone-injection-controller.js`，建立当前生成→解析→追加→保存→读取→渲染链路。
2. 固定路线字段：`title`、`goal`、`seed`、`why`、`pace`、`sourceMessageId`、`createdAt`、`order`、`enabled`。
3. 确认第二轮不覆盖第一轮的既有计划；新增路线使用稳定来源消息标识和递增排序。
4. 将“本轮解析数量”作为页面反馈来源；区分：保存成功、无可操作路线、格式未识别、保存失败。
5. 保持普通文本原样保存和显示，不把普通文本伪装成路线。

**阶段验收：** 给定两轮各两条合法 `StoryPlan`，内存模型和读取结果包含四条；给定第二轮普通文本，历史可见且收到“未识别路线”语义，不产生假路线。

### 阶段 B：第二轮路线可见性修复

1. 修改 `appendStoryOracleTurn()` 及相关渲染调用，使每轮解析出的路线继续追加，而不是覆盖既有路线。
2. 修复路线与助手消息的来源绑定：优先使用当前响应对应的 `sourceMessageId`；无法绑定时进入明确的未关联路线区域，不静默丢失。
3. 路线工作台按最新生成优先显示，保证第二轮路线进入当前可见区域；消息流仍保持时间顺序。
4. 生成完成后传递本轮解析结果到页面状态，形成短暂收据：
   - 有路线：`本轮生成 N 条路线，已加入路线工作台`；
   - 无路线：`本轮已保存，但没有识别到可操作路线`；
   - 格式异常：`本轮文本已保存，路线格式未识别`。
5. 收据不写入历史，不作为消息气泡，不覆盖用户输入或路线工作台。

**阶段验收：** 第一轮和第二轮路线同时存在；第二轮位于路线工作台当前顶部；普通回复仍可见；页面反馈与解析数量一致。

### 阶段 C：页面信息架构重构

1. 在 `src/story-oracle.js` 中把页面组织为：标题区、活动路线区、短暂收据、路线工作台、消息流、输入区。
2. 路线工作台由独立工作项组成，不再使用“路线也是聊天气泡”的结构；每条路线独立容器、独立操作区和来源信息。
3. 活动路线改为纵向列表，每条一行，长标题自然换行，禁止横向滚动和省略截断作为主阅读方式。
4. 用户消息明确输出为右侧独立消息块；助手说明输出为左侧阅读块；StoryPlan 正文从助手说明中剥离。
5. 保持输入区固定在页面底部，工具与模式切换为低强调入口，发送保持唯一主操作。
6. 保留现有事件委托、ARIA、继续讨论、开始/停止引导、删除和清空动作，不伪造宿主写回。

**阶段验收：** DOM 层级能区分路线工作项、用户消息、助手说明和输入区；第二轮路线不再依赖滚动到底部才能发现。

### 阶段 D：TASKOW 风格视觉收敛

1. 仅修改 `.pm-story-oracle-*` 组件族，复用 `docs/CSS-TOKENS.md` 已登记语义 token。
2. 页面使用白色/页面表面背景，深蓝强调色只用于唯一主操作和明确活动状态。
3. 删除路线采用危险色文字或弱状态标记，不使用大面积红色背景。
4. 路线工作项默认不使用完整描边；以留白、表面差异、字重、分组间距和必要的弱分隔建立层级。
5. 删除普通会话区的气泡尾部、左右聊天气泡比例和同质化消息间距在 Story Oracle 内的影响；不改普通会话规则。
6. 调整标题、目标、辅助信息、操作区和输入区垂直节奏，优先使用 `space-2/3/4`、标准字体和行高 token。
7. 覆盖亮色、暗色、focus-visible、disabled、移动窄屏和 reduced-motion；不新增裸颜色、裸字号、裸间距、裸圆角、阴影或 z-index。

**阶段验收：** 页面具备明显独立视觉；长标题不截断；按钮层级清晰；删除不再出现大块红色；普通聊天页面不受影响。

### 阶段 E：构建与原型级验证

1. 修改后立即读回所有目标区段，确认没有部分 hunk、未声明字段或残缺模板。
2. 执行 `npm.cmd run build`，确认 `index.js` 由源码重建。
3. 执行 `node --check index.js`。
4. 按助手已确认的原型范围做最低验证：两轮路线累计、无路线反馈、最新路线可见、用户消息存在、置顶路线换行、通知消失、删除样式。
5. 执行 `git diff --check` 和差异范围核对。
6. 记录未覆盖项：真实 SillyTavern DOM、刷新恢复、聊天切换、存储损坏、取消竞态、亮暗主题实机、窄屏和键盘焦点。
7. 不自动提交或推送，除非助手另行明确授权。

## 4. 依赖与阻塞关系

- 阶段 B 依赖阶段 A 的字段和排序契约；
- 阶段 C 依赖阶段 B 已能稳定提供“当前路线集合”和“本轮新增路线”；
- 阶段 D 可与阶段 C 的纯样式部分并行，但必须在页面 DOM 层级稳定后收敛，避免 CSS 反复返工；
- 阶段 E 依赖 A-D 全部完成，并且 `index.js` 必须重新生成。

## 5. 回滚方案

- 数据层回滚：恢复 `src/story-oracle-model.js` 与 `src/story-oracle.js` 的路线追加/排序/收据改动，保留原有 store 数据；
- 视觉层回滚：仅回退 `.pm-story-oracle-*` 样式和页面模板，不触碰普通聊天、世界书、主聊天或其他模块；
- 构建层回滚：从上一个已知可用提交重新生成 `index.js`，不手工编辑 bundle；
- 若第二轮路线仍无法确认进入可见区域，优先退回“路线预览+明确解析收据”，不显示虚假的“已加入工作台”。

## 6. 风险控制

- 普通文本不是路线，不能因为用户要求“看得到第二轮”就强行猜测并建卡；
- 新增字段必须保持旧数据可读取，缺失 `pace` 时按空值处理；
- 最新优先排序会改变历史阅读顺序，因此路线工作台和消息流必须分离；
- 无描边不等于无层级，若表面和留白不足，路线会融入页面背景，需通过结构和排版补足；
- 过多活动路线会压缩消息区，输入区必须保持可见，路线列表应使用内部滚动；
- 自动收据若脱离页面生命周期，可能晚到重绘旧页，原型阶段记录为未覆盖风险。
