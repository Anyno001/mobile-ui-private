# Story Oracle 对话/路线分屏与 TASKOW 交互重构实施计划

## 1. 计划来源与修订理由

- **来源**：助手本轮明确需求——基于 TASKOW 的真实导出页重做剧情助手交互，要求简约、互动感强，并解决固定路线挤压聊天区的问题。
- **废止前提**：旧版“路线工作台置于消息流之前、活动路线常驻页面顶部”的结构已由实际 UI 反馈否定。它让 `.pm-story-oracle-active-plans` 与 `.pm-story-oracle-plan-workbench-wrap` 同时抢占纵向空间，后者还允许占内容区 `50%`，聊天区只能获得剩余空间。
- **TASKOW 取证**：`Task/In Progress.png` 以独立任务列表承载卡片；`Chat.png` 让聊天内容从标题下延续到固定输入区；`Task/Action.png` 将低频操作收进局部菜单；`Project details.png` 用 tab 在同一任务的不同信息面间切换。不能只抄圆角卡片，却把其信息架构反着用。

## 2. 目标与硬边界

### 目标

1. 以 **对话 / 路线** 两个平级 tab 取代同屏的顶部活动路线区与半屏路线工作台。
2. 对话页的消息流从 tab 下方延展至输入区；生成路线不会再压缩聊天高度。
3. 路线页以 TASKOW 式摘要工作项展示：状态、标题、目标、轮次/时间/节奏；完整细节按需展开。
4. 生成成功时，对话页显示可点击收据 `本轮生成 N 条路线 · 查看`；点击后切换至路线页并聚焦最新一轮。
5. 路线管理保留开始/停止引导、继续讨论、删除；低频操作从三按钮平铺收敛到局部菜单。

### 不变边界

- 不改变 `STORY_ORACLE_STORE_VERSION`、现有 scope 数据、`StoryPlan` 解析、排序字段、注入 key 与主聊天写入边界。
- 不删除现有路线、聊天历史、世界书选择或剧情助手设置。
- 不修改普通聊天、社区、日历、今日风向等其他模块。
- 不复制 TASKOW 文案、图像、头像、进度条或无对应数据的任务字段。

## 3. 目标信息架构与交互

### 3.1 页面结构

```text
navbar（返回 / 剧情模式 / 关闭）
view tabs：对话 | 路线 {数量徽标}
当前主视图（唯一可滚动内容区）
composer（常驻底部）
```

- **对话页默认打开**：用户问题、助手说明和短暂收据都在此处；不渲染完整路线列表，也不渲染顶部“已注入大纲”。
- **路线页**：按最新生成轮次优先展示路线卡；tab 标题显示总数。新生成结果将路线 tab 标记为新内容，点击收据进入后清除该标记。
- tab 是页面视图切换；`剧情聊天 / 剧情参谋`仍是模型工作模式切换。这两个概念不得复用同一状态变量或控件。

### 3.2 路线卡行为

- 默认摘要：状态（引导中/待选择）、标题、目标、来源轮次、生成时间、推进节奏。
- 点击卡片主体：展开/收起起始迹象与契合点；展开状态只保留在当前页面运行时，不写入 Story Oracle store。
- `⋮` 局部菜单：开始引导/停止引导、继续讨论、删除线路；删除维持低强调危险项。
- 启用状态由路线卡和 tab 元信息表达；不再额外占用常驻列表高度。

### 3.3 生成反馈

- 有合法路线：对话流尾部附近出现一行可点击收据，显示数量并提供“查看”。
- 无路线或格式异常：保留现有明确文案，但不展示跳转操作。
- 点击“查看”切换至路线 tab，并在路线列表顶部展示本轮路线；不改变既有全局排序与历史数据。

## 4. 实施步骤与依赖

### A. 先冻结新视图状态与 DOM 契约

1. 在 `src/story-oracle.js` 内增加**运行时 UI 状态**：当前视图、当前轮次聚焦标识、路线详情展开集合、路线局部菜单状态、新路线提示状态。
2. 状态按聊天 scope 初始化；切换剧情模式时保持当前视图的明确策略（默认保留视图，若无路线则路线页显示空态）。
3. 将页面模板改为 navbar → tab → 单一主内容区 → composer；删除 `renderStoryOracleActivePlans()` 的页面挂载与 `pm-story-oracle-plan-workbench-wrap`/消息区同屏堆叠。
4. 在 `scripts/check-contracts.mjs` 中移除旧的“工作台在消息流前、活动条置于滚动区外”断言，改为 tab、唯一主滚动区、路线计数、可点击查看收据、路线局部菜单的正负契约。

**验收点**：DOM 中不再同时存在常驻活动路线区和完整工作台；对话/路线由独立的 `aria-selected` tab 表达；composer 仍在主内容区外。

### B. 实现对话页与生成跳转

1. 对话页只渲染用户消息、助手说明、生成收据；路线正文继续从助手说明剥离。
2. 将生成结果的 `parsedResult.plans` 数量及新增来源轮次传给 UI 状态；不要通过重新解析所有历史猜测“本轮”。
3. 有路线收据提供 `查看` action；点击后切换路线视图，设置最新来源轮次的视觉焦点。
4. 保持无路线、格式未识别、取消、保存失败的现有语义，不能因为改 tab 而丢失诊断性反馈。

**验收点**：多条路线存在时，对话页聊天高度不因路线数量而减少；用户可一击进入本轮路线；普通文本不会出现“查看路线”假入口。

### C. 实现路线页、摘要卡、详情与菜单

1. 重写 `renderStoryOraclePlans()` 为路线页专用列表：最新优先，按 `sourceMessageId` 标识来源轮次；保留现有 plan id、title、goal、seed、why、pace、enabled。
2. 设计摘要卡默认字段与详情区，保证卡片主体和菜单按钮的点击行为不冲突。
3. 新增委托 action：切换详情、打开/关闭路线菜单、开始/停止引导、继续讨论、删除；保留忙碌态、只读态、键盘 Escape/菜单外点击关闭、焦点回到触发按钮的既有菜单纪律。
4. 删除三枚按钮横向平铺；继续讨论改入菜单或作为展开详情中的次操作，开始/停止引导是唯一清晰状态动作。

**验收点**：默认一屏能看到多条路线摘要；长标题换行；操作不再常驻三等分；路线执行行为与改造前一致。

### D. CSS 收敛与可访问性

1. 仅改 `.pm-story-oracle-*`；移除旧的 `max-height:50%` 与顶部活动路线布局。
2. tab 使用现有表面、文字、accent、border、space、radius token；活动 tab 用细下划线或轻量表面状态，不新增裸视觉值。
3. 对话和路线各自使用单一 `flex:1` 滚动区；路线列表卡片复用 TASKOW 的表面色块+留白语言，不复制其业务元素。
4. 补齐 tab 的 `role=tablist/tab/tabpanel`、`aria-selected`、`aria-controls`；卡片详情按钮 `aria-expanded`；菜单 `aria-haspopup/menu` 与焦点恢复。
5. 保持 320px 下 tab、卡片标题、菜单与输入区可用；不通过压小字体或触控区解决空间问题。

**验收点**：无路线时对话页占满内容区；路线再多也只在路线视图内滚动；切换 tab 不造成页面整体双滚动或 composer 消失。

### E. 构建、范围核对与回退

1. 读回改动区，确认旧双常驻结构、`max-height:50%` 和三按钮路线操作区已不存在。
2. 重建 `index.js`；运行语法、Story Oracle 专项、契约和 `git diff --check`。
3. 最小手动原型核对：对话页聊天可用高度、路线页多卡滚动、收据跳转、详情展开、菜单动作、开始/停止引导、删除、无路线反馈。
4. 回退时仅恢复 `src/story-oracle.js`、`styles/core.css`、`scripts/check-contracts.mjs` 与重建 bundle；数据 store、解析和注入层不回退也不迁移。

## 5. 风险与控制

- **状态漂移**：视图/展开/菜单是运行态，不能误写进持久化数据；切换聊天后必须重置或按当前 scope 重建。
- **点击冲突**：卡片主体展开与 `⋮`/开始引导必须 stop propagation 或精确委托，不能出现点菜单顺手展开卡片。
- **新路线定位**：必须以本次响应生成的 `sourceMessageId` 为依据，不能把“最新排序第一条”误判为本轮路线。
- **可访问性**：tab、详情、菜单必须有状态属性和焦点回归；不能为了“互动感”只做视觉动画。
- **回归边界**：不改变 `appendStoryOracleTurn()`、`parseStoryPlans()`、路线注入构建与 store version，避免 UI 重构碰坏数据链。

## 6. 计划自查

这版以一次明确 tab 切换换回稳定聊天空间，代价是路线不会永远露在聊天首屏；但生成收据、数量徽标和一击跳转保障其可发现性。它比把工作台折叠在聊天上方更干净：没有两个常驻区域，也没有用户每次都要在被压扁的聊天页里处理折叠状态。
