# 桌面模块图标自定义与一键美化包实施计划

## 1. 计划来源与已确认边界

本计划来源于助手直接需求及本轮代码库侦察，未依赖外部设计或审查文档。

已确认范围：

- 增加七个桌面入口的自定义图片图标：会话、联系人、设置、日历、今日风向、剧情助手、底部“发布一条”。
- 图片支持透明底，复用现有裁剪交互骨架，但不得沿用背景裁剪器写死的 `330:450 + JPEG` 输出契约。
- 随后增加独立的一键美化包，内容限于作者设定的主题配置、现有背景范围与七个桌面图标。
- 背景范围保持不变：桌面背景、全局背景、当前联系人背景；不新增逐功能页面背景。
- 不开放返回、关闭、发送、编辑、删除等操作图标，不改变应用名称、顺序、功能状态或业务数据。
- 完整数据备份与可分享美化包必须分离；美化包禁止携带 API、聊天、联系人、社区、日历等业务或隐私数据。

## 2. 现状证据与实施约束

- `src/interactive-scene-views.js:85-94` 直接注入七个桌面入口的内联 SVG；这些 SVG 来自共享 `src/icons.js`，不能全局替换，否则会污染其他页面的操作图标。
- `src/cropper.js:5-6,148-175` 将裁剪比例写死为 `330/450`、输出宽度写死为 600，并转换成 JPEG；透明图标需要独立的 1:1、保留 Alpha 的输出模式。
- `src/settings-backup-controller.js:27-97` 与 `src/settings-backup.js:133-221` 已有完整备份的 capture/apply/persist/rollback 事务骨架，并已覆盖主题及三层背景。
- `src/settings-templates.js:85-140` 当前主题页已承载主题色与三层背景设置；图标编辑应作为同一“外观”领域下的独立分区或子页，不把页面堆成不可维护的长表单。
- `docs/BASELINE.md` 要求保留宿主生命周期、持久化键与完整数据导入导出回归；`AGENTS.md` 要求 UI 变更同步遵守 token、亮暗、focus、disabled、移动端与机器契约。
- bundle 存在 120% 体积门禁，禁止引入图片处理依赖；使用浏览器原生 Image/Canvas/Blob/IndexedDB 能力。

## 3. 目标数据模型与职责边界

### 3.1 桌面图标标识

建立稳定白名单，不允许导入文件任意扩展键：

- `chat`
- `directory`
- `settings`
- `calendar`
- `todayTrend`
- `storyOracle`
- `community`

每项只影响桌面入口展示。渲染器接收 `appId + fallbackSvg`，合法自定义资源返回受控 `<img alt="" aria-hidden="true">`，缺失、损坏或解码失败时仅回退该项内置 SVG。

### 3.2 持久化分层

新增独立外观资产存储边界，不把大体积 Data URL 塞进 `ST_SMS_THEME`：

- 轻量清单：schema 版本、每个 appId 的资源元数据与引用。
- 二进制/数据 URL：复用 `PhoneModeDB/kv` 的 IndexedDB 存储能力。
- 运行时：规范化后的七项图标映射与解码失败隔离状态。

推荐 schema：

- `schemaVersion: 1`
- `icons[appId]`: `null` 或 `{ mime, width, height, byteLength, dataUrl/resourceKey }`

规范化器必须丢弃未知键、拒绝错误 MIME/尺寸/容量，并保留合法项；单项损坏不得导致全部图标不可用。

### 3.3 美化包格式

独立格式：

- `format: "tianyin-appearance"`
- `schemaVersion: 1`
- `meta`: 名称、作者、说明、创建时间
- `appearance.theme`: 经白名单提取和规范化的外观字段
- `appearance.backgrounds.desktop`
- `appearance.backgrounds.global`
- `appearance.backgrounds.currentContact`
- `appearance.icons`: 七项白名单图标

`currentContact` 是可移植语义，不导出原 `bgLocal` 键；导入时仅映射到导入者当前有效联系人。没有有效联系人时，预览中标记为“不会应用”，其余内容仍可导入。

## 4. 分阶段实施步骤

### 阶段 A：建立通用、可回归的裁剪模式

1. 将 `openCropper` 的背景专用常量参数化：标题/提示、比例、输出尺寸、输出 MIME、质量策略、是否保留透明、背景填充策略与容量上限。
2. 保持现有背景调用默认行为完全等价：`330:450`、600 宽、JPEG 压缩与当前容量控制不能回归。
3. 新增图标模式：1:1、透明画布、256×256、PNG 或透明 WebP；首版以可验证兼容性为准，禁止在不支持透明 WebP 的环境静默转为 JPEG。
4. 图标模式允许图片四周留白，不强制 cover 裁掉细长图案；拖动、滚轮、触摸缩放、取消与对象 URL 释放沿用现有生命周期。
5. 在解码前后检查文件 MIME、原始文件大小、自然尺寸、输出尺寸和输出字节数；拒绝 SVG、GIF、远程 URL 与超限数据。

**验收检查点 A：** 原背景裁剪快照/契约不变；透明 PNG 裁剪后 Alpha 保留；取消、重复打开、异常解码均不泄漏 overlay/object URL。

### 阶段 B：实现七项桌面图标资产存储

1. 新建单一 owner 的图标 schema、白名单、规范化、加载、保存、删除、物化与清理接口；存储失败必须返回可诊断错误。
2. 复用现有 IndexedDB `PhoneModeDB/kv`，为图标清单和资源键建立明确前缀；不得更名或复用背景键。
3. 加载时兼容“无图标存储”的旧环境，默认空映射；未知高版本拒绝读取并保留原数据，不静默覆盖。
4. 保存单项图标采用事务式顺序：校验并暂存新资源 → 更新清单 → 删除旧孤儿资源；中途失败恢复旧清单并清理新资源。
5. 删除/重置单项只影响该 appId；“全部恢复默认”需先捕获清单快照并支持失败回滚。
6. 插件安全清理流程必须删除图标清单与图标资源；不得触碰宿主或其他扩展数据。

**验收检查点 B：** 刷新和重开后七项资源可恢复；单项损坏只回退该项；存储失败不留下半更新清单或孤儿资源。

### 阶段 C：接入桌面渲染与图标设置 UI

1. 在桌面视图引入统一 `resolveDesktopAppIcon(appId, fallbackSvg)`，仅改造 `src/interactive-scene-views.js:85-94` 的七个入口。
2. 保持按钮的 `data-app`、`data-action`、`aria-label`、标题、DOM 顺序和点击行为不变；自定义 `<img>` 仅为装饰内容。
3. 为桌面图标建立统一尺寸/contain/透明背景样式，使用既有语义 token 或经登记的局部私有 token；不得污染共享 SVG 规则。
4. 在主题设置中增加“桌面图标”入口或独立子页，显示七项当前预览、选择图片、裁剪确认、单项重置与全部重置。
5. 上传后先预览裁剪结果，持久化成功后再刷新桌面；保存失败恢复原预览并给出自然语言错误。
6. 确保 320px、亮色、暗色、键盘 focus、触控命中区和图片加载失败占位均可用。

**验收检查点 C：** 七项均可独立设置/重置；底部“发布一条”包含在内；所有非桌面 SVG 与业务行为零变化。

### 阶段 D：把图标纳入完整数据备份

1. 在完整备份 capture/apply/persist/clear 链加入规范化后的桌面图标资产，提升完整备份 schema 版本。
2. `parseBackupData` 兼容旧备份缺少图标字段：解释为空映射或保留导入事务当前值的策略必须明确并写入断言；不得把旧备份误判损坏。
3. 对当前版本严格校验图标字段；未知未来高版本明确拒绝并提示升级。
4. 将图标资源持久化并纳入现有 `runBackupTransaction` 回滚；任何图标写入失败必须恢复主题、背景和其他已应用数据。
5. 完整备份导出继续保持现有隐私警告，不作为分享美化的入口。

**验收检查点 D：** 新完整备份往返等价；旧备份仍可导入；模拟图标持久化失败时完整事务回滚成功。

### 阶段 E：实现独立美化包导出、校验、预览与导入

1. 新建外观包专用 serializer/parser，不复用完整备份字段白名单；导出对象只能从主题外观字段、三层背景语义和七项图标组装。
2. 导出前物化 IndexedDB 图标与背景资源，计算单项/总包大小；超限时明确列出超限资产，不生成残缺包。
3. 增加元数据编辑：主题名称、作者、说明；默认值可为空或使用应用标题，但不得读取联系人名称填充作者信息。
4. 导入采用两段式：解析与完整预校验 → 预览覆盖范围 → 助手确认后事务应用。解析阶段不得写入任何状态。
5. 预览显示主题模式/主题色、桌面与全局背景是否包含、当前联系人背景的目标或跳过状态、七项图标覆盖清单、包版本与总大小。
6. 建立外观专用事务：捕获当前主题、三层目标背景和图标资产 → 应用内存 → 持久化 → 刷新外观；任一失败按反向顺序恢复。
7. 当前联系人背景仅在存在有效当前联系人时写入对应 `bgLocal` 键；导入包不得携带或恢复作者原始联系人键。
8. 导入完成后即时调用现有主题、背景与桌面刷新链；若宿主限制导致必须重开，应准确提示，不伪装即时生效。
9. 美化包输入只接受 JSON；图片必须是受支持的自包含 Data URL，禁止远程 URL、SVG、GIF、脚本或额外未知资源。

**验收检查点 E：** 美化包不含任何业务/隐私字段；导出再导入外观等价；无联系人时仅跳过 currentContact；任一资产失败时全部外观恢复。

### 阶段 F：自动化验证、宿主回归与独立验收

1. 扩展 `scripts/check-cropper.mjs`：背景默认契约、1:1 透明模式、格式/尺寸/容量拒绝、对象 URL 清理。
2. 扩展 `scripts/check-contracts.mjs`：七项白名单、唯一渲染 owner、自定义图片只出现在桌面入口、ARIA/DOM/action 不变、CSS token 与选择器边界。
3. 扩展备份/行为检查：新旧 schema、未知高版本、损坏单项、完整备份事务回滚、美化包字段白名单与隐私负例。
4. 增加外观包 round-trip、无联系人、部分字段、空包、超限包、未知键、伪 MIME、错误 Base64、图片解码失败测试。
5. 逐条运行 build、syntax、cropper、behavior/contracts 与全量 `npm.cmd run check`，再执行 `git diff --check`；区分既有基线失败与本轮回归。
6. 在真实 SillyTavern 宿主验证：七项设置与重置、刷新恢复、亮/暗主题、320px、触摸裁剪、桌面/全局/当前联系人背景、美化包预览、成功导入和失败回滚。
7. 核对构建产物 `index.js` 已包含源码变化且未突破体积门禁；清理临时图片、测试包和日志。
8. Code 模式正式交付前调用独立验收专家逐项核验；存在 blocking/major 时修复并复验，不能用主助手自检替代。

## 5. 测试矩阵

### 正常路径

- 七项分别上传透明 PNG、透明 WebP、带留白图案并刷新恢复。
- 单项重置与全部重置。
- 主题色 + 桌面背景 + 全局背景 + 当前联系人背景 + 七图标整包往返。
- 只含部分图标或只含主题的美化包。

### 异常与边界

- JPEG 上传到图标模式：允许解码但输出必须为透明能力格式，空白区保持透明。
- SVG/GIF/远程 URL、错误 MIME、损坏 Base64、超大文件、超大像素、零尺寸图片。
- localStorage/IndexedDB 写入失败、清单成功而资源失败、资源成功而清单失败。
- 导入期间关闭手机、切换联系人或当前联系人失效；目标上下文变化时放弃 currentContact 写入并回滚或显式跳过，禁止写错联系人。
- 老完整备份、新完整备份、未知高版本完整备份；老美化包、未知高版本美化包。
- 一个图标损坏时其余六项正常显示。

### 隔离回归

- `src/icons.js` 共享 SVG 输出不变。
- 桌面七按钮 action、顺序、ARIA 与触控区域不变。
- 聊天、联系人、社区、日历、今日风向和剧情助手业务数据不进入美化包。
- 现有背景裁剪、头像裁剪（若消费同一入口）、完整备份、清理全部数据均不回归。

## 6. 风险与控制

- **存储膨胀：** 256×256 统一降采样，限制单图、总图标与总包字节数；资产走 IndexedDB，主题配置保持轻量。
- **透明度丢失：** 图标模式禁止 JPEG 输出；编码后重新解码验证 Alpha 能力和尺寸。
- **共享图标污染：** 只在桌面七入口增加解析层，不改变 `src/icons.js` 常量语义。
- **半套外观：** 图标单项更新、完整备份、美化包分别使用明确事务与补偿顺序。
- **联系人误写：** 导入前锁定当前 storageId/persona 地址，提交前复核；地址变化则停止 currentContact 应用。
- **隐私泄漏：** serializer 采用正向白名单并加负例断言，不从完整备份对象做删除式裁剪。
- **启动性能：** 不在每次渲染重复读取/解析全部资源；加载后缓存规范化映射，更新时精确失效。
- **包体积门禁：** 不引入第三方裁剪/压缩库，构建后检查 bundle 上限。

## 7. 回滚策略

- 阶段 A 可回退参数化裁剪入口并恢复原背景默认调用；不得手工修改构建产物。
- 阶段 B/C 可移除桌面解析层和设置入口；遗留图标键因无人消费不会影响旧版，但应提供精确清理路径。
- 完整备份 schema 回退时保留解析旧版本能力；不得让新版备份被旧代码静默部分导入。
- 美化包功能可整体移除而不影响完整备份和既有主题/背景数据。
- 运行时导入失败优先执行事务快照恢复；若恢复也失败，提示勿刷新并立即导出当前完整备份，保留可诊断错误阶段。
- 所有源码回滚后重新执行 build 生成 `index.js`，禁止手工裁剪 bundle。

## 8. 完成定义

只有同时满足以下条件才可标记完成：

- 七个桌面入口（含“发布一条”）可使用透明图片并可靠恢复默认。
- 现有背景裁剪行为、共享 SVG 与七入口业务动作无回归。
- 图标资产具备 schema、规范化、容量限制、IndexedDB 持久化、清理和失败回滚。
- 完整备份可保全图标且兼容旧备份。
- 独立美化包仅包含主题、现有三层背景语义和七项图标，支持预览、确认、事务导入与安全回滚。
- 自动化门禁、真实宿主回归、构建产物核对及独立验收全部闭环；任何 blocking/major 均已修复并复验通过。

## 9. 计划自检

这份计划贴合当前桌面视图、裁剪器、主题/背景和备份事务结构，没有把操作 SVG 或逐功能背景偷偷扩进范围。最需要在实施时保持警惕的是两点：一是图标资产与完整备份的事务补偿不能只测成功路径；二是当前联系人背景必须锁定导入目标，不能在用户切换上下文后写错联系人。若实施者跳过这两处，前面的“可回滚”就只是文档装饰。
