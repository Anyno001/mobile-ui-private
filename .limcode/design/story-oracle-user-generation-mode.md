# 剧情助手 User 生成模式与全局 User 库设计

## 1. 已确认目标

在现有剧情助手中新增用户可见模式 **User 生成**：

- 用户可用一句模糊需求启动，例如“我想要一个魅魔角色”；
- 助手根据已收集素材进行最少必要追问，不展示机械式长问卷；
- 素材足够后生成完整 User Persona 文本；
- 成品可保存到全局共享的 **User 库**，并一键复制；
- User 库沿用现有路线工作台的页面布局、卡片层级、展开方式和局部操作菜单；
- 不写入、覆盖或注入 SillyTavern 的 User Persona、主聊天、世界书或角色卡；
- 允许成人向 User 角色内容，但成人内容中的角色必须明确为成年人。

## 2. 非目标

首版不实现：

- 写入或切换 SillyTavern User Persona；
- 主聊天、世界书或扩展提示注入；
- 路线启用、推进速度、引导强度等剧情路线语义；
- JSON/角色卡导出；
- 标签、搜索、分类、收藏、多版本对比；
- 自动生成头像；
- 多套模板市场或可配置问卷编辑器。

## 3. 现有实现约束

- 当前 UI 模式白名单为 `question`、`advisor`，历史模式另含遗留 `lorebook`：`src/story-oracle-model.js:1-4`。
- 当前 Story Oracle 数据按 `storageId` 放在 `scopes` 下；路线也属于当前聊天 scope：`src/story-oracle-model.js:131-160`。
- `appendStoryOracleTurn()` 只在 `advisor` 模式解析并保存路线：`src/story-oracle-model.js:261-285`。
- 路线工作台由 `renderStoryOraclePlans()` 与 `renderStoryOraclePlan()` 渲染：`src/story-oracle.js:38-57`。
- 页面当前采用“对话 / 路线”双视图：`src/story-oracle.js:89-110`。
- 存储加载存在 IDB、localStorage fallback、只读保护和串行保存契约：`src/story-oracle-storage.js:28-81`。
- UI 必须遵守语义 token、亮暗主题、320px 窄屏、focus-visible、disabled 和至少 44px 主触控目标：`docs/CSS-TOKENS.md`。

## 4. 信息架构

### 4.1 模式入口

模式菜单新增：

- 剧情聊天
- 剧情参谋
- User 生成

内部模式标识使用稳定、无展示语义的 `user-generation`。必须同时进入 UI 模式白名单、历史模式白名单和模式标签映射，禁止只改其中一处导致历史静默落入 `question`。

### 4.2 User 生成模式页面

保持现有顶部模式切换和底部输入区；中间采用两个平级标签：

- **对话**：展示本模式独立访谈历史；
- **User 库**：展示全局共享成品。

进入 User 生成模式时第二个标签显示“User 库”，不继续显示“路线”。剧情聊天与剧情参谋的现有标签和行为不变。

### 4.3 User 库卡片

视觉沿用路线工作台：全宽工作项、标题可换行、摘要为主信息、详情折叠、局部操作菜单、最新成品优先可见。

卡片操作：

1. **复制**：卡片级主操作；折叠状态也可使用；
2. 展开/收起全文；
3. 继续修改：将当前成品作为只读上下文带回 User 生成对话，用户后续提交才调用模型；
4. 删除：低强调危险操作，需沿用现有确认方式或提供明确二次确认。

User 卡片不得显示路线的启用、停止引导、推进速度或主聊天注入状态。

## 5. 对话与生成状态协议

### 5.1 追问原则

模型根据用户当前输入、User 生成历史和当前修订目标判断缺口。只追问会改变角色核心方向或内容边界的字段：

1. 世界观/时代与种族变体；
2. 核心性格及反差；
3. 与目标互动对象的关系方向；
4. 关键外貌与穿着倾向；
5. 能力、限制或代价；
6. 是否包含成人/亲密内容及偏好边界；
7. 输出规格：极简版、成品版、进阶版。

不得要求所有字段逐项作答。已能安全合理补全的次要字段可补全或省略；不得把补全事实伪装成用户已明确提供。

### 5.2 受控输出协议

User 生成模式使用独立系统契约。模型每轮只能返回以下状态之一：

- `collecting`：仍需素材，包含一条自然语言追问；
- `complete`：包含可入库成品；
- `revision`：基于指定成品生成修订后的完整新成品。

推荐采用可解析包裹：

- `<UserGenerationState>`：`status`、`missing`、`question`；
- `<UserGenerationResult>`：`title`、`summary`、`content`。

解析器必须：

- 限制区块数量与字段长度；
- 拒绝未闭合、重复、缺少 `title/content` 的结果；
- 从对话展示文本中剥离控制标记；
- 格式损坏时保留普通回复到历史，但不得误存为成品；
- 明确显示“回复已保存，但未识别到可保存的 User 成品”。

不得用“包含角色名”“出现生成完成”等自然语言猜测替代结构解析。

## 6. 模板抽取

只抽取 `wenfengyouhua-skills-v2/yokenken-main/references/character-structure.md` 的角色结构语义，不整体注入目录。

首版成品模板：

- 角色名；
- 履历：年龄、显著特征、日常穿着、嗜好习惯、必要家庭/出身关系；
- 与目标互动对象的关系；
- 与自己、外人及必要具体角色的关系；
- 他者评价；
- 可选亲密场景；
- 作者笔记/角色使用提示。

模式规格：

- 极简版：身份、外貌、性格、关系、关键行为边界；
- 成品版：默认完整结构；
- 进阶版：在成品版基础上增加条件化关系/状态校准信息。

文风优化与犹疑校准规则不整体并入系统提示；只保留角色模板所需的最小质量约束，避免提示词膨胀和职责污染。

## 7. 成人内容边界

- 允许用户明确请求成人向角色、人设、关系和亲密场景内容；
- 一旦生成内容涉及性行为或露骨性设定，相关角色必须明确为成年人；
- 年龄缺失且成人内容是核心需求时，追问或在不冲突的情况下明确设为成年人；
- 用户明确要求未成年人参与成人内容时不得生成该部分；
- 成人内容开关只影响 User 生成模板，不修改剧情聊天、剧情参谋或全局模型设置。

## 8. 数据模型与持久化

### 8.1 独立全局存储域

User 库不放入 `scopes[storageId]`，也不复用 `StoryPlan`。建议新增独立持久化模型与键，例如：

- 主键：`ST_SMS_USER_GENERATION_V1`；
- fallback：`ST_SMS_USER_GENERATION_V1_LOCAL_FALLBACK`；
- shape：`{ version: 1, items: [] }`。

独立存储的理由：

- User Persona 是跨角色聊天共享对象；
- 避免修改现有 Story Oracle V1 scope schema 和路线清理语义；
- 避免分支继承、清空线路、清空当前模式历史误操作全局 User 库；
- 独立损坏、恢复和只读保护，不连带破坏剧情助手历史。

### 8.2 UserGenerationItem

```text
{
  id,
  title,
  summary,
  content,
  sourceMessageId,
  createdAt,
  updatedAt,
  order
}
```

约束：

- `id` 稳定且去重；
- `title`、`summary`、`content` 设独立字符上限；
- `content` 为空的对象不得进入库；
- 默认最多保存有限数量成品，超限时拒绝新增并给出可恢复提示，不静默删除最旧项；
- normalize 兼容缺少未来可选字段的历史对象；
- 删除只删除指定 item；
- 修订默认产生新成品，首版不静默覆盖旧版本。若产品最终选择覆盖，必须显式确认并更新 `updatedAt`。

### 8.3 历史归属

User 生成对话历史仍可沿用 Story Oracle 的 `modes['user-generation']`，按当前聊天隔离，以避免不同角色上下文和世界书资料串线；User 成品库则全局共享。

因此：

- 访谈上下文：当前聊天隔离；
- 成品 User Persona：全局共享；
- 从全局库“继续修改”时，当前聊天只得到该成品的只读修订上下文，不自动复制全部旧访谈。

## 9. 复制契约

复制目标只能是 `item.content`，不得夹带标题、摘要、控制标签、按钮文案或状态提示。

执行顺序：

1. 优先使用 `navigator.clipboard.writeText(content)`；
2. Clipboard API 不可用或被拒绝时，使用受控 textarea 选择 + `document.execCommand('copy')` 兼容路径；
3. 两条路径均失败时显示明确失败文案，不伪装成功；
4. 成功后按钮短暂显示“已复制”，随后恢复“复制”；
5. 复制期间阻止重复激活，并维护可访问状态；
6. 页面销毁时清理反馈计时器和临时 DOM。

## 10. 请求生命周期与异常路径

复用现有请求 serial + AbortController 模式：

- 模式切换、聊天切换、页面关闭或用户取消后，旧请求晚返回不得写历史或保存成品；
- 模型响应解析完成但 User 库保存失败时，对话历史与成品库状态必须可诊断，不得显示“已保存到库”；
- User 库只读或损坏时仍允许在对话中生成并复制，但禁用保存按钮并说明原因；
- 重复点击保存不得产生重复 item；
- 空成品、超限成品和格式损坏成品均不得进入库。

## 11. UI 与可访问性

- 复用 `.pm-story-oracle-*` 组件族和路线工作台配方，必要时增加语义明确的 User 子类；
- 不新增裸颜色、间距、字号、圆角、阴影、z-index 或动效值；
- 同一区域只保留一个主操作，复制为卡片主操作，删除保持低强调危险操作；
- 覆盖亮色、暗色、320px 窄屏、focus-visible、disabled、loading；
- 标题和正文允许自然换行，不使用 ellipsis 隐藏关键内容；
- 复制、展开、菜单、删除均使用原生按钮并具有可访问名称；
- 展开状态同步 `aria-expanded`，忙碌状态同步 `aria-busy` 或等价语义；
- 列表重绘前后保留 User 库滚动位置。

## 12. 预计修改范围

- `src/story-oracle-model.js`：新增模式白名单与 User 生成响应解析契约；
- `src/story-oracle.js`：模式标签、双视图、User 生成提交分支、结果保存入口、复制与卡片交互；
- 新的最小 User 库 model/storage 模块，或在明确职责下扩展现有文件；不得复用路线对象；
- `styles/core.css`：仅 `.pm-story-oracle-*` / User 库子组件；
- `scripts/check-story-oracle.mjs`：模式、解析、历史隔离、库 normalize、保存失败和复制目标契约；
- `scripts/check-contracts.mjs`：UI token、ARIA、选择器和复制按钮契约；
- 备份/导入导出所有者：实施前必须搜索真实消费链并把新全局键纳入，禁止仅依赖 localStorage/IDB 而让用户备份漏掉 User 库；
- `index.js`：只由构建生成，不手工编辑。

## 13. 验收标准

### 功能

- 模式菜单出现 User 生成，其他模式行为不变；
- “我想要一个魅魔角色”会根据缺口提出最少必要问题；
- 素材足够时生成结构完整的 User Persona；
- 有效结果可保存到全局 User 库，跨不同角色聊天仍可见；
- User 生成访谈历史不跨聊天串线；
- 卡片折叠和展开状态均可复制完整 `content`；
- User 库不产生任何主聊天、世界书或 User Persona 写入/注入；
- 成人向合法请求可生成，涉及性内容的角色明确为成年人；
- 继续修改不会静默覆盖原成品。

### 异常与持久化

- 刷新后 User 库恢复；
- IDB 失败可使用 fallback；主存储损坏时不覆盖原始数据；
- 保存失败、复制失败、解析失败均有准确文案；
- 取消请求、模式切换、聊天切换和晚返回不产生幽灵成品；
- 容量超限时拒绝新增并提示，不静默淘汰；
- 备份导出与导入后 User 库守恒。

### UI

- User 库沿用路线工作台布局语言，但不存在路线专属控件；
- 亮暗主题、320px 窄屏、键盘操作、焦点、禁用和 loading 均可用；
- 关键正文不截断，触控目标符合项目标准；
- 无新增未登记视觉硬编码或 `!important`。

### 工程门禁

- 新增专项契约测试覆盖正例、负例、格式损坏、重复保存、跨聊天共享、访谈隔离和复制失败；
- 构建、语法检查、`check:story-oracle`、`check:contracts`、全量检查与 `git diff --check` 通过；
- 构建产物实际包含新模式、User 库和复制逻辑；
- 正式交付前由独立 Acceptance Expert 逐项验收；存在 blocking/major 时修复后复验。

## 14. 关键决策

- 全局共享的是成品库，不是访谈历史；
- 复用路线布局，不复用路线数据结构和注入语义；
- 独立 User 库存储，避免污染 Story Oracle scope；
- 默认生成完整新版本，不静默覆盖旧成品；
- 成人向能力属于 User 生成模式自身，且以成年人边界为前提；
- 首版只保存和复制，不连接 SillyTavern Persona 写入能力。
