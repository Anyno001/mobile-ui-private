# Story Oracle 手机应用模块集成设计

## 1. 目标与边界

将 GitHub 仓库 `https://github.com/namelessone88/story-oracle` 的 Story Oracle 核心能力集成为当前虚拟手机内的独立应用。应用遵循现有 TASKOW/phone-mode 的页面、窗口、导航、生命周期、存储和 CSS 约定，不复制上游悬浮窗口视觉。

本次集成保留五类能力：

1. 普通剧情问答；
2. 世界书阅读与可审查的编辑预览；
3. 剧情参谋、方案与弧线；
4. 回复校正与差异预览；
5. 角色工坊。

明确不包含变量状态诊断、变量树编辑、变量补丁应用及相关自动任务。该能力从本项目的功能列表、UI、提示词、解析器、适配器、存储、测试和验收标准中排除，不以“暂时未实现”名义保留入口。

不直接复制上游 `index.js` 或 `style.css`，不运行时远程加载上游代码，不使用上游 `StoryOracleAPI` 作为嵌入接口。上游仓库当前快照为 `main`/v1.71.0，未发现标准 `LICENSE` 文件；实现必须保留作者署名、来源 URL、快照版本和本地改动说明，未确认再分发授权前限定为私用集成。

## 2. 已核实的宿主输入与约束

- `src/main.js` 是模块组合根，按固定顺序安装手机模块。
- `PHONE_UI_PAGES`、`createPhonePageController` 和 `section[data-phone-page]` 管理手机页面。
- `renderPhoneDesktop()` 输出桌面应用按钮，`interactive-scenes.js` 负责桌面动作与页面切换。
- 宿主提供统一 AI 调用器 `createAiClient`、SillyTavern 上下文读取和 `gatherContext`。
- 宿主提供世界书名称/正文读取能力，可读取当前聊天关联的世界书和条目。
- 宿主没有确认可用于世界书正文、聊天消息或角色资料安全写回的等价接口；因此编辑、校正和角色应用首期只能预览、差异、复制或导出，不得伪造成功。
- 宿主已有扩展提示注入能力，可供参谋方案在用户明确采纳后走独立命名空间；注入必须有清理和失败诊断。
- 宿主生命周期通过 `__pmEnd`、页面切换和资源 owner 管理取消与清理；Story Oracle 不启用未经验证的后台保活。

## 3. 总体方案

采用“上游纯逻辑抽取 + 当前宿主适配层”：

```text
Story Oracle 上游逻辑
  ├─ 提示词、解析器、补丁校验、业务算法
  └─ 上游 ST DOM / 事件 / 存储 / API 耦合
             │
             ▼
当前项目 Story Oracle 适配层
  ├─ 手机页面与生命周期
  ├─ 现有 CSS token、按钮、表单和错误状态
  ├─ 宿主 AI 与上下文收集器
  ├─ 独立 Story Oracle 存储
  ├─ storageId + mode 任务隔离
  └─ 显式、可审查的预览/写回边界
```

建议职责拆分：

- `src/story-oracle/`：提示词、纯解析器、补丁校验和业务算法，不直接操作 DOM；不包含变量状态诊断/编辑逻辑。
- `src/story-oracle-model.js`：应用状态、模式、会话、错误和版本化归一化。
- `src/story-oracle-storage.js`：独立存储、历史限制、损坏数据诊断和兼容读取。
- `src/story-oracle-ai.js`：宿主 AI 调用、超时、取消、错误分类和请求身份校验。
- `src/story-oracle-view.js`：限定在 Story Oracle 根节点下的手机样式。
- `src/story-oracle-page.js`：页面渲染、事件委托、返回桌面、加载/卸载和资源清理。
- 宿主接线只改 `interactive-scene-constants.js`、必要的状态归一化、`phone-lifecycle.js`、`interactive-scene-views.js`、`interactive-scenes.js` 和 `main.js`。

## 4. 五类功能适配

### 4.1 普通剧情问答

保留独立侧聊、上下文深度选择、角色卡/世界书读取、问答、重试、停止、导入导出和运行概要。历史按 `storageId + mode` 隔离，不写入主聊天。使用宿主 AI 和上下文收集器，不维护第二套连接请求实现。所有输入和模型输出进入 DOM 前必须转义或使用安全文本节点。

### 4.2 世界书阅读与编辑预览

读取当前聊天可用世界书、条目筛选、预览和问答。编辑操作只生成结构化 patch、差异和导出结果；在宿主没有正文写回与撤销接口时，应用按钮不可用或不存在。目标书名与 uid 必须来自当前快照，不能由模型自行决定。

### 4.3 剧情参谋、方案与弧线

保留参谋问答、单步方案、方案状态和弧线预览。方案数据使用独立命名空间，任务绑定 `storageId`、聊天身份、模式和 AbortController。只有用户明确采纳后，才允许通过宿主扩展提示能力写入独立 `story-oracle` key；切换聊天、关闭应用、放弃方案时必须清理。未经验证的弧线后台任务不启用。

### 4.4 回复校正

保留正文作用域识别、结构块保护、选段校正、差异预览和重试。自动校正默认关闭。由于当前未确认安全的消息更新、swipe、撤销契约，首期只提供预览、复制或导出，不直接修改主聊天。选段请求只发送用户明确选择的内容，按字符偏移从后往前应用到预览结果，未选内容不得进入请求。

### 4.5 角色工坊

保留访谈、简报、锻造、草稿修订、精简、预览、差异和导出。草稿只进入独立临时状态；角色资料或世界书正文写回在未确认宿主契约前不提供。解析器必须拒绝缺字段、重复字段、非法 patch 和格式漂移，不能静默生成半成品。

## 5. 数据、生命周期与安全

- 所有 Story Oracle 数据按 `storageId` 隔离，模式历史再按 `mode` 隔离；不复用聊天、社区、日历或今日风向 store。
- 配置、运行概要、方案/弧线、校正草稿和角色工坊草稿使用独立命名空间与版本字段。
- schema 变更必须兼容读取历史格式；解析失败保留原始数据并进入可恢复错误态，禁止静默清空。
- 每个异步任务携带 `storageId`、聊天身份、模式、请求序号和 AbortController；迟到结果不得写入新聊天或新页面。
- 关闭应用时保存允许持久化的状态，取消前台任务，清理临时 UI、事件监听和 Story Oracle 扩展提示。
- 所有写回类能力遵循快照、预检、显式确认、执行、刷新、结果记录；当前宿主契约不足时只展示预览/导出。
- 用户输入、模型输出、错误信息和来源文本不得未经安全处理直接注入 HTML；日志不得包含聊天正文或 API 密钥。

## 6. 宿主改动边界

- `src/interactive-scene-constants.js`：增加 `story-oracle` 页面标识。
- `src/interactive-scene-model.js`：增加合法页面和兼容归一化，不破坏既有状态版本。
- `src/phone-lifecycle.js`：增加 Story Oracle 页面容器，并接入关闭、最小化、切聊天和恢复时的任务失效与清理。
- `src/interactive-scene-views.js`：增加桌面图标，沿用既有按钮结构。
- `src/interactive-scenes.js`：增加打开、返回和页面恢复动作，不在社区业务分支混入 Story Oracle 逻辑。
- `src/main.js`：安装 Story Oracle 模块并注入已确认的 AI、上下文、世界书读取、扩展提示和存储依赖。
- 不修改现有聊天、社区、日历、今日风向业务数据和存储语义。

## 7. 验收标准

### 桌面与导航

- 桌面显示 Story Oracle 图标，点击只显示 Story Oracle 页面。
- 返回桌面、退出手机、最小化、恢复页面和切换聊天不残留 DOM、定时器、事件监听或旧任务结果。
- 页面状态按聊天恢复且不串台；既有页面和普通模式不回归。

### 功能

- 五类纳入能力逐项具备进入、发送、错误、停止/重试和持久化边界；未纳入的变量状态诊断/编辑没有入口、模块或验收项。
- 普通问答不写主聊天；参谋只有在用户采纳后写独立扩展提示。
- 世界书、消息和角色写回在宿主契约不足时明确显示为预览/导出，不显示虚假的“已应用”。
- 写回失败、宿主 API 缺失、上下文缺失、模型截断、重复任务和聊天切换均可诊断且不静默丢数据。

### 视觉与可访问性

- 不加载上游全局 CSS；新样式限定在 Story Oracle 根节点。
- 复用现有手机 token、导航、按钮、表单、弹层和错误状态。
- 触控目标、窄屏布局、焦点、ARIA、禁用态和减少动态效果完整。

### 工程验证

- 先运行语法、构建、现有全量检查，再运行 Story Oracle 专项契约测试。
- 专项测试覆盖页面归一化、storageId/模式隔离、异步任务失效、写回预检、普通解析器、正文作用域、选段偏移、草稿 patch、撤销快照和重复初始化。
- 构建产物必须确认包含新增页面和样式。
- 正式完成前必须由独立只读验收专家输出 `blocking/major/minor/pass`；存在 blocking/major 时修复并复验，未收敛不得宣布完成。

## 8. 风险与实施顺序

主要风险为上游许可证边界、宿主写回契约缺失、上游体量、生命周期泄漏和样式污染。固定 v1.71.0 快照，不自动拉取；升级必须重新做差异审查。

实施顺序：

1. 手机页面、桌面入口、导航和空状态；
2. 普通问答与独立侧聊历史；
3. 世界书只读、编辑预览与剧情参谋单步方案；
4. 回复校正预览；
5. 角色工坊预览/导出；
6. 每阶段构建、专项契约、宿主回归和独立验收。

任何阶段若需要扩大宿主写回接口或改变本设计，必须先修订计划并重新确认。
