# 今日风向架构边界

本文记录“今日风向”的当前生产架构、使用边界和验证方式，可独立于内部实施计划阅读。

## 产品边界

今日风向以当前聊天中的单个角色为中心，展示世界态势、个人风评、相关势力和相关动态。世界预设跨对话共享；角色资料按 `storageId` scope 隔离。初始化根据世界书编译四模块规则和初始内容；本轮/自动更新以一次统一 AI 调用更新内容。完整档案仅供 APP 使用，正文只接收精简社会状态。

不复制社区、帖子、聊天或天气模块；不注入世界态势、势力详情、事件历史、已归档事件或模块 Prompt；不以任意数值或百分比表达态度；不合并生成链和注入链。

## 完整产品树

```text
今日风向
├─ 世界态势
│  ├─ 当前风向：一句话
│  └─ 世界观生成的环境项：名称 + 一句话
└─ 当前角色：角色名
   ├─ 个人风评
   │  └─ 世界观圈层〔敌对/厌恶/中立/喜欢/信任〕一句话评价
   ├─ 相关势力
   │  ├─ 父势力：介绍、关键资料、对角色〔状态〕评价
   │  │  └─ 子势力：直接嵌套并展示同类资料
   │  └─ 外部关联：独立势力卡片及同类资料
   └─ 相关动态
      ├─ 正在追踪：名称〔类型/当前阶段〕、起因、涉及主体、阶段记录、最新阶段
      └─ 已完结：名称〔类型/完结结果〕、起因、涉及主体、完整阶段记录、最终结果
```

手机桌面

      ├─ 顶栏：返回桌面、标题、开始/停止、本轮生成、总设置

页面使用既有 `data-phone-page` 与内部 view state，不增加 URL 路由；事件唯一分发方式为 `data-action`。AI 生成/推进使用星光图标，运行时必须 disabled、`aria-busy=true` 并显示 loading；刷新既有项使用刷新图标。

```text
APP 总设置
├─ 总控制：开始/停止；本轮生成
├─ 世界预设：当前预设下拉；新建；删除（禁止留下悬空 scope）
├─ 初始化：世界书〔必选〕；已有正文〔可选且默认勾选〕；追加要求；生成/重新初始化
├─ 总体调用：手动/自动；每 N 楼执行一次
├─ 正文注入：独立开关
└─ Prompt 总览：世界态势、个人风评、相关势力、动态总/突发/流言/地下线规则的查看、编辑和重新生成
```


```text
世界态势内容页
├─ 项目：名称 + 一句话；单项刷新
├─ 本模块生成
└─ 设置：态势项目的新增/编辑/删除；模块规则查看/编辑/重新生成；保存/取消

个人风评内容页
├─ 圈层〔固定状态〕一句话评价；单项刷新
├─ 本模块生成
└─ 设置：圈层名称/范围的新增、编辑、重新生成、删除；模块规则查看/编辑/重新生成；保存/取消

相关势力内容页
├─ 势力树：卡片默认展示名称、介绍、关键资料、对角色状态和评价；子势力直接嵌套
├─ 外部关联：同样直接展示关键资料
├─ 扫描并生成；手动添加
└─ 设置：模块规则查看/编辑/重新生成；保存/取消
   └─ 势力编辑：名称、介绍、父势力（可空）、外部关联（多选）、关键资料、五档状态、评价；保存/取消

相关动态内容页
├─ 正在追踪：事件卡片展示名称〔类型/阶段〕、起因、主体、阶段记录、最新阶段；推进、编辑、标记完结
├─ 已完结：事件卡片展示名称〔类型/结果〕、阶段记录、最终结果；查看、删除
├─ 推进全部；手动创建事件
└─ 设置：追踪上限、仅实际进展追加、自动完结、完结归档；突发开关/概率/规则；流言开关/规则；地下线开关/规则；动态总规则；保存/取消
```

圈层固定状态不可用户设置项编辑。势力卡片必须直接展示高频资料，不能强制进入二级详情。首次使用最多两次主要点击：桌面进入空状态后新建预设；随后点击生成。无世界书时阻止初始化；初始化失败不留下半预设，保留表单供重试。

## 状态协议

评价仅允许 `hostile`（敌对）、`dislike`（厌恶）、`neutral`（中立）、`like`（喜欢）、`trust`（信任）。

事件 `type` 仅为 `normal`（常规）、`incident`（突发）、`rumor`（流言）、`underground`（地下线）；`lifecycle` 仅为 `active` 或 `archived`。`stageLabel` 是世界观化的 2–8 字短语，描述进程而不表达评价。完结 `outcome` 仅为 `resolved`、`failed`、`terminated`、`inconclusive`、`confirmed`、`debunked`、`absorbed`。

active 事件追加阶段并更新 `latestStage`；完结后移入 archived，不再自动推进或注入。未证实流言保持 rumor，证实或证伪后归档；地下线升级为公开事故时归档旧事件并新建 incident，不得改写旧事件 type。势力必须拒绝重复 ID、悬空 `parentId` 与父子循环。

`TodayTrendPreset` 保存版本、来源、四模块规则、模块 schema 和动态规则。`TodayTrendScope` 保存角色与预设绑定、运行设置、注入开关、世界条目、圈层、势力与 active/archived 动态。所有外部输入、AI 结果和导入数据必须先 normalize。

## 生成、提交与注入

```text
世界书 + 可选正文 -> context -> prompts -> generation -> commit -> storage
                                             |                 |
                                          scheduler          injection -> host prompt
view <-------------------------------------- actions
```

初始化和统一更新分别至多调用一次 AI；解析不完整或校验失败时整单拒绝，不能部分提交。每个 scope 只有一个 in-flight 任务；手动任务可替换旧任务，自动重复触发合并一次，聊天/预设切换或关闭时取消，迟到结果不得提交。自动模式只按新增完成的助手正文计楼；成功才推进 checkpoint，手动成功也同步 checkpoint。

注入是无 AI 纯函数，只使用全部圈层评价、全部势力对角色评价和 active 事件最新阶段：

```text
[角色名·个人风评]
圈层｜状态｜一句话评价

[角色名·势力关系]
势力｜状态｜一句话评价

[角色名·事件追踪]
事件｜stageLabel｜latestStage
```

必须使用全角 `｜` 并按完整行裁剪；不得从 UI 文案反向解析或执行模块 Prompt。提交成功后才刷新注入；注入失败必须恢复 APP 快照并补偿旧 prompt。注入默认关闭。

## 模块职责与生产边界

- `today-trend.js`：安装与依赖装配，禁止承载业务逻辑。
- `model`：版本、归一化、不变量、状态映射；`storage`：IDB/fallback、preset/scope 读写；`commit`：快照、原子提交、注入补偿。
- `context`：世界书、正文增量、角色与 scope 标识；`prompts`：初始化与统一更新 envelope；`generation`：AI 调用、解析和刷新入口；`scheduler`：计楼、合并、取消。
- `injection`：无 AI 的纯格式化；`view` 与四个模块视图、`settings-view`：APP 壳、模块内容/设置及初始化表单；`actions`：唯一 `data-action` 分发点。
- `check-today-trend.mjs`：模型、页面、生成、调度、事务和注入专项测试入口。

当前实现由 `main.js` 安装，已接入手机桌面、页面生命周期、持久化、备份、分支继承、统一生成和独立正文注入。所有 `src/*.js` 必须严格少于 800 行；复杂逻辑继续保持模块化，不得回填到安装层或既有大文件。

## 使用说明

1. 输入 `/phone` 打开手机，在桌面进入“今日风向”。
2. 首次使用选择至少一本世界书；可选择是否参考当前正文，并可填写追加要求。生成成功后才会写入预设和当前角色资料，失败不会留下半成品。
3. “本轮生成”会用一次 AI 调用更新四个模块。自动模式按新增的助手正文计楼；编辑、删除、滑动重生成和用户消息不会重复计数。
4. 世界预设可供不同对话复用；角色资料按当前聊天 `storageId` 隔离。创建分支时复制角色资料，但重置生成任务和楼层 checkpoint。
5. 正文注入与生成开关相互独立，默认关闭。启用后还需在“上下文预算”中给“今日风向”分配非零比例，否则不会产生正文 prompt。
6. 正文只接收圈层评价、势力对角色评价和 active 事件最新阶段；世界态势、势力详情、事件历史和 archived 事件不会注入。
7. 备份包含今日风向预设与角色资料。导入失败会回滚；备份仍可能包含聊天数据或 API Key，不得公开。

## 故障排查

- 看不到 APP：确认扩展已更新，并重新打开 `/phone`。
- 无法初始化：确认当前是有效角色聊天、至少选择一本可读世界书，并检查 AI 配置。
- 开启注入但正文无内容：检查当前角色是否已有资料、注入开关是否启用，以及“今日风向”预算是否大于 0。
- 自动模式不触发：确认“开始运作”、模式为“自动”、N 楼大于 0；只有新完成的助手正文计数。
- 生成失败：原资料不会被部分覆盖；修复网络、模型输出或世界书问题后重试。

## 验证与性能边界

- `npm run check` 会重建 bundle，并执行语法、AI、交互、日历、预算、权限、静态合同和今日风向专项测试。
- 模型对预设、scope、圈层、势力、事件、阶段和文本长度设置硬上限；正文注入受统一 token 预算约束并按完整行裁剪。
- 自动调度当前需要扫描聊天快照以识别编辑、删除和滑动重生成。自动化覆盖 82 条消息及竞态路径；超长真实对话的界面响应仍应在 SillyTavern 中人工观察。
- Node 自动化不能替代宿主验证。发布前仍需在真实 SillyTavern 检查世界书 API、主/独立 AI、`setExtensionPrompt`、IndexedDB、分支、窄屏、软键盘和原聊天/社区/日历回归。
