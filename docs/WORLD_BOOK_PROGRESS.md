### 旧字段 fallback 风险结论

- fallback 本身只处理一个书名字符串，不会枚举或加载整个世界书库。
- 被选中的世界书会由 `loadWorldInfo(bookName)` 完整加载，然后在本地规范化、排序和过滤。
- `maxChars` 只限制最终输出，不限制单本世界书的加载、排序和扫描内存。
- 因此普通世界书风险较低；异常庞大的单本世界书可能带来线性增长的瞬时内存和主线程开销。

- 已补齐 `aria-expanded`、`aria-controls` 和详情面板稳定 ID。

## 本次完成：展开详情后的模块矩阵窜行

### 根因

渲染侧每行包含“栏目名 + 会话 + 日历 + 穿搭 + 社区”共 5 个网格项，但旧 CSS 仍按“栏目名 + 3 个模块”声明 4 列。第 5 个网格项被自动排入下一行，导致后续栏目持续错位。

### 已实施修改

- 布局改为 `minmax(0,1fr) repeat(4,minmax(24px,34px))`，始终保持 1 个栏目列和 4 个模块列，同时允许模块列随手机组件宽度收缩。
- 模块矩阵间距收紧为 `6px 4px`；矩阵内眼睛按钮使用 `width:100%` 和 `min-width:0`，避免固定 38px 按钮撑破收缩轨道。
- 不再依赖只反映浏览器视口宽度的 340px 媒体查询决定矩阵列宽，覆盖桌面宽视口下手机组件缩放至 0.6 的可达状态。
- CSS 契约测试从 `WORLD_BOOK_MODULES` 推导模块数量，并验证响应式模块轨道及按钮收缩约束，防止模块数与网格列数再次漂移。
- 未改动世界书渲染和业务逻辑；修复范围仅限网格列契约及其测试。

### 验证结果

- `node scripts/check-behavior.mjs`：通过。
- `node scripts/check-contracts.mjs`：通过。
- `npm run check`：通过，包含重新构建和全部检查脚本。
- `git diff --check`：通过，仅报告 Windows 行尾转换提示。
- 独立验收确认原始窜行根因已修复；桌面宽视口下缩小手机组件的边界风险已通过不依赖视口断点的可收缩网格消除。
