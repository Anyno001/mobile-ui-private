# 各层规则

## 一、履历

履历是角色容器最顶部的客观底盘，先于所有关系段出场。只写可核实的静态事实，不写态度。

### 字段规则

| 字段 | 写什么 | 不写什么 | 格式范例 |
|---|---|---|---|
| 姓名 | 纯名 | 别称、绰号、解释 | `周维` |
| 年龄 | 纯数字 | "看似""苍老""年轻" | `32` |
| 显著特征 | 名词短语，含发色五官等可核实外貌事实 | 修饰语、因果、频率、性格形容词 | `黑色大背头，丹凤眼，左眉骨旧疤两厘米` |
| 日常穿着 | 名词短语 | "总是""习惯性""偏爱" | `深色衬衫，银色领带` |
| 嗜好习惯 | 名词或动词短语 | "用来""为了"等动机 | `长跑` |
| 家庭关系 | `关系=姓名` | 形容词、关系评价 | `父亲=周建国` |

### 隐性规则

- 任何暗示社会角色的词（职业、头衔、身份位）不进履历
- 用户没提供的字段直接省略，不字段，不写"暂无"
- 一律第三人称极简陈述
- 不加"似乎/像是/大概"等不确定词

### 合格范例

```text
## 履历
姓名：周维
年龄：32
显著特征：黑色短发，左眉骨旧疤两厘米
日常穿着：深色衬衫
嗜好习惯：长跑
家庭关系：父亲=周建国 母亲=（已故） 妹妹=周宁
```

### 违规范例与修正

| 违规 | 问题 | 修正 |
|---|---|---|
| `日常穿着：总穿深色衬衫` | "总"是频率判断 | `日常穿着：深色衬衫` |
| `嗜好习惯：长跑（缓解压力用）` | 括号内带动机 | `嗜好习惯：长跑` |
| `家庭关系：与父亲关系紧张` | 关系评价 | `家庭关系：父亲=周建国` |
| `显著特征：沉稳内敛` | 性格形容词 | 删除，性格由关系段承担 |
| `职业：建筑设计师` | 社会角色信息 | 删除，职业只在作者笔记出现 |
| `显著特征：帅气` | 主观评价 | 改为具体外貌事实，如`丹凤眼，下颌线硬` |

## 二、关系段

关系段是新人设卡的核心。每个关系是一个完整截面：经历→句式→公开→独白。角色在不同关系中自然显出不同面。

### 关系段排列顺序

1. 最在乎的关系排前面——关系排列顺序本身就是性格信息，AI 读到最前面的关系会赋予最高权重
2. 具体角色名在前，笼统对象（需简单定性，如"外人""上级""陌生访客"）放最后
3. 用户对象用 `<user>` 标记（运行时替换为玩家名字）

### 经历 规则

- 客观事实，可多条拆分写
- 禁止文学修饰：不写"那次刻骨铭心的离别"，写"2018年离开Y公司"
- 禁止点评：不写"从此他变了"，不写"这件事影响深远"
- 禁止因果指向：不写"父亲十岁时离家，从此不再提家事"——前半句是事实，后半句是结论
- 可为空（笼统对象段通常为空）

合格范例：

```text
经历：2018年因X项目事故离开Y公司，同年加入Z设计院
经历：父亲2015年确诊，2017年去世
经历：大学时同寝室四年
```

违规范例：

| 违规 | 问题 |
|---|---|
| `经历：那场事故彻底改变了他` | 点评 |
| `经历：父亲去世后他再没回过家` | 因果指向 |
| `经历：那个雨夜的分别让他至今难以释怀` | 文学修饰 |

### 句式 规则

只写可观测的表面特征，不写功能解释和画面评价。

格式模板：

```
句式：台词字数在XX字为主，XX多/少，XX句为主，偶尔使用XX
```

合格范例：

```text
句式：台词字数在4-8字为主，感叹号和问号多，陈述句为主，偶尔使用省略号中断表达
句式：台词字数在20字以上为主，逗号多，陈述句为主，偶尔使用省略号中断表达
句式：台词字数在10字以内为主，句号收尾居多
```

违规范例：

| 违规 | 问题 |
|---|---|
| `句式：语气急促，多用短句` | "急促"是情绪标签 |
| `句式：句子长，用逗号舒缓` | "舒缓"是功能解释 |
| `句式：省略号断在半句` | "半句"是画面评价 |
| `句式：说话慢条斯理` | 整条都是性格描写 |
| `句式：不带语气词` | "不带"是否定动作清单 |

### 公开 规则

- 面对此人真实的台词构成——每一句都是角色说出口的话
- 4-7 句（笼统对象段）或 3-7 句（具体关系段）
- 每句承载多重信息：读者能从台词反推出对方刚说了什么/双方关系/角色态度
- 不解释自己为什么这样说
- 不像独白——每一句都是对对方的回应

### 独白 规则

- 角色的内心想法——以语料形式呈现，不是叙述性描述
- 表里如一时写"同上"/"无"/"似乎和嘴上说的一样"
- 允许与公开矛盾——这是活人感的来源
- 禁止解释公开的动机（"嘴上说没事，其实是因为不想让他担心"——后半句在替前半句做心理分析）
- 可以闪躲、岔开、悬置——绕开问题本身就是真相
- 不让角色总结自己
- **假独白禁令**：角色不能用旁白方式描述自己的动作。"说不想，手还搁在那里"是第三人称旁白越界——角色正在那里，不会用"手还搁在那里"描述自己的手。必须在独白中改为"意识到"自己的行为：反问（"我手为什么还放在那里？"）、感叹（"我居然还没走！"）、困惑（"怎么还在发抖呢……"）——判断标准是角色在发现自己还是在旁观自己

独白中角色可以审视自己的经历和公开场合的自己，但必须：
- 用具体的事做承担物，不用抽象标签
- 用"观察+犹豫收尾"而非"宣布结论"（"我习惯先安排好计划再做事，这个习惯…可能是从十五岁开始的吧"而非"我处理所有事情的方式都是先把它攥住"）
- 角色可以回头看，但不能替自己做心理诊断

### 关系：自己

"关系：自己"是新人设卡新增的关系段。角色对自身的经历、公开表态和真实想法分别在不同子字段中呈现。

- 经历：个人经历事实（原来放在履历的"可核实经历"移入此处）
- 句式：同其他关系段格式
- 公开：3-7 句被问及自己时说的回应语料——"还行""没什么好说的""我自己选的"这类极简回应本身就是性格信息
- 独白：4-7 句对自身核心习惯或经历的真实想法语料——允许自省，但遵守假独白禁令和"不总结自己"规则

与角色自述（personality 字段）的边界：自述是全局性的身份叙述（我是谁、我怎么变成这样的），此处独白是针对特定经历的态度声明（我对这件事怎么看）。删掉此段独白后自述里不应已有同样的信息。

### 三层互解释边界

- 允许：独白与公开呈现矛盾
- 允许：独白写"同上"/"无"标记表里一致
- 禁止：独白解释公开的动机
- 禁止：经历带因果指向
- 规则：**三层可以矛盾，但不能互相注释**

## 三、他者评价

- 评价者不出现在任何 `## 关系：X` 的标题中
- 评价者是局外人/旁观者，不是与角色有直接关系的人
- 至少两种视角（长期共事/短期接触/敬佩/困惑等）
- 至少一个"没想通"的钩子
- 不出现介绍式标签（"他是那种XX的人"）
- 议论者承认看不透，才合格
- **用不确定口吻猜测，不用确定性心理诊断**：旁观者不可能看到角色心理，只能看到行为后猜测心理。"他控制欲强吗？是有点，我觉得是他有点不安吧"合规；"他控制欲强是因为他怕"违规——后者是替角色做心理分析

## 四、亲密场景

### 出现条件

角色与某个具体对象存在亲密/性接触语料时启用。亲密语料和日常互动的语言结构完全不同——不是"更激烈版"而是"另一个维度"。

### 触发方式

两种方式，按项目复杂度选择：

**方式一：<if> 条件触发**（适合有数据库的项目卡）

包在 `<if>` 块内，使用状态变量切换。位于他者评价之后、校准段之前（如有）或作者笔记之前。

```text
## 亲密场景
<if db="db.关系表.where('对象','user').where('亲密度','>=',80).exists()">
3-7 句亲密关系语料
</if>
```

**方式二：KEY 触发**（适合轻量卡，不需要数据库）

写成独立世界书条目，`keys: ["角色名", "亲密"]`。对话中出现相关关键词时加载。

### 语料规则

- 每句承担关系动作，不只是描写
- 角色意识到自己的行为与意图不符时，用反问/感叹/困惑表达，不用旁白描述（同独白段的假独白禁令）
- 不触发时不消耗上下文 token

## 五、校准

### 出现条件

仅进阶版 / 用户要求分阶段时启用。成品版不含校准段。

### 规则

- 包在 `<if>` 块内，使用状态变量切换
- 只用不确定词 + 可见证据（"似乎/像是/好像/然而/偏偏/说不准"）
- 1-3 句，推荐 1 句
- 不下定论
- 不泄漏变量值（变量名与数值只在 `<if>` 表达式内）
- 不解释关系段
- 不展开为阶段调制说明
- 不替关系段下结论

合格范例：

```text
## 校准
<if db="角色.压力 > 60">最近他安静得有些过分了，每句话就那么几个字。</if>
<if db="角色.信任 < 30">最近他是不是经常一个人离开？</if>
```

## 六、作者笔记

### 格式

作者笔记以 ❌ 错误示例列表开头，再跟原因说明和正确方向：

```text
## 作者笔记
❌ "典型错误写法1"
❌ "典型错误写法2"
❌ 具体违规模式描述

（原因说明：为什么这些是错的，本角色最容易演成什么刻板印象）
→ 正确方向：一句话说明应该怎么写
```

❌ 列表的作用是给 AI 具体的否定锚点——AI 知道什么不对后更容易避免。每条 ❌ 必须是实际会出现的典型错误，不是空泛的"不要写坏东西"。

### 三条验收条件（硬约束）

❌ 列表之后的内容无固定模板，但必须通过以下三条验收条件，缺一即违规：

**条件一：必须指向卡内一句具体台词**

不是"写到关系段时"，是"写到面对上级那句'我先把手头能确认的部分交出来'时"。不指向具体台词 = 违规。

**条件二：必须包含至少一个作者自己没有解决的问题**

这个问题不能是修辞性的（"他到底是个什么样的人呢"），必须是具体的、可检验的——"他到底会不会解释"可检验，"他是个什么样的人"不可检验。

**条件三：不可转移**

把作者笔记里的角色名和台词引用替换成另一个角色的名称和台词后，剩余的句式结构仍然能成立，就是公式违规。检验方法：写完后挖空角色名和具体台词，看剩余骨架是否在另一张卡里也能填空通过。

### 参照样本（结构互不相同，防止收敛）

**样本 A（卡住了，没写出来）**

> 写到他对上级说"我先把手头能确认的部分交出来"时，本来想让他加半句解释为什么只剩这些——但加上去之后他就不像他了。是他在防备还是他真的不需要解释，我写完也没分清。

验证：指向具体台词 ✓；待解问题="是防备还是不需要解释"可检验 ✓；不可转移 ✓

**样本 B（写出了一个意外发现）**

> 他对老友说"做完以后……再说吧"，那个省略号比他平时任何一句话都长。我没打算给他留这个口子，是关系段写着写着自己冒出来的。这个口子到底通向哪里，我现在也不知道。

验证：指向具体台词 ✓；待解问题="口子通向哪里"可检验 ✓；不可转移 ✓

**样本 C（职业信息自然出现）**

> 写到诊室那段，前三句他全在解释——解释病情、解释方案、解释为什么不用另一种药。写到第四句才发现我在写"标准医生"。改成他边说边翻抽屉找零食。不确定他找零食是"不把病人当外人"还是"根本不在乎这间诊室里发生了什么"——这两个方向差别很大，我还没想好往哪边走。

验证：指向具体台词序列 ✓；待解问题="不把病人当外人vs根本不在乎"可检验 ✓；职业信息在纠正刻板印象过程中自然出现 ✓；不可转移 ✓

### 职业信息专则

- 职业、头衔、社会身份类信息不进履历
- 只能在作者笔记中出现
- 出现时必须绑在一个具体的刻板印象纠正过程中，不能作为独立标签

## 七、输出结构铁律

1. 外层容器标签名 = 角色名本身（中文，不带前缀后缀）
2. 容器内第一节必须是 `## 履历`
3. 履历后接关系段，最在乎的排前面，笼统对象放最后
4. 他者评价在关系段之后
5. 亲密场景（如有）位于他者评价之后，包在 `<if>` 块内或独立条目
6. 校准段（如有）包在 `<if>` 块内，位于亲密场景之后、作者笔记之前
7. 作者笔记位于最后
8. 关系段之间不写过渡句、总结句、连接词——并置不递进
9. 角色容器外不再加额外档案块
10. 最终交付纯中文（`<if>` 表达式语法本身除外；`<user>` 占位符除外）
11. 关系段字段名不加方括号——`经历`而非`[经历]`，冒号已足够标记字段边界

## 八、模式开关

| 模式 | 输出内容 | 前提 |
|---|---|---|
| 成品版（默认） | 履历 + 关系段 + 他者评价 + 亲密场景 + 作者笔记 | 无动态变量需求 |
| 进阶版 | 履历 + 关系段 + 他者评价 + 亲密场景 + 校准 + 作者笔记 | 用户明确要求分阶段 + 存在状态变量 |
| 极简版 | 履历（精简）+ 1-2 个关系段 + 他者评价 | 配角/token 紧张 |
